# COVID-19 Epidemiological Surveillance Dashboard (Synthetic Data)

An interactive Quarto dashboard demonstrating epidemiological surveillance and 
data visualization techniques applied to synthetic patient-level COVID-19 data.

## Overview

This project simulates a public health surveillance dashboard — the kind used to 
monitor an outbreak's demographic profile, geographic spread, clinical severity, 
and time trend — built entirely on **synthetic data**. It is a portfolio piece 
demonstrating an end-to-end RWE/health-surveillance workflow: SQL extraction from 
a relational database, data cleaning, KPI design, geospatial analysis, time series 
modeling, and dashboard development.

**Tabs:**
- **Overview** — landing page
- **Demographics** — age/sex structure, race distribution, outcome-stratified indicators
- **Spatial Distribution** — case incidence by county (rate-adjusted), diagnosis centers on map
- **County Performance** — hospitalization volume, length of stay, lethality by county (with small-N suppression)
- **Temporal Trends** — daily epidemic curve (cases, hospitalizations, deaths)
- **About** — data source, methodology, and author

## Data & Disclaimer

All data is **synthetic**, generated by [Synthea](https://github.com/synthetichealth/synthea), 
an open-source patient population simulator. No real patient data, no real institution, 
and no real geographic incidence pattern is represented. Hospital names, patient 
identities, and case counts are entirely fictional (Massachusetts is used only 
because it is Synthea's default synthetic population geography).

This dashboard's structure and analytical approach are inspired by professional 
experience building real epidemiological surveillance systems in public health, 
but contains no institutional data, names, or figures from any real project.

## Reproducing Locally

1. Generate a Synthea population (Massachusetts, COVID-19 module) or use a 
   pre-built export.
2. Load into PostgreSQL/Supabase using the schema referenced in `2_data_extraction.R`.
3. Run `2_data_extraction.R` to pull and shape the cohort, saving `tidy_data.rds`.
4. Render the dashboard: `quarto render index.qmd`.

## Methodology Notes

- **Severity levels** (0–4) are a constructed ordinal proxy — Synthea does not 
  natively flag ICU status, so severity is inferred from oxygen therapy and 
  mechanical ventilation procedure codes, escalating to "deceased" for deaths 
  within a 30-day window of diagnosis.
- **30-day mortality window**: deaths are attributed to the COVID episode if they 
  occur within 30 days of diagnosis. In this dataset, 349 of 357 deceased patients 
  (98%) fall within that window; the remainder (max. 68 days) were retained given 
  their clinical plausibility and negligible effect on aggregate figures.
- **ARIMA forecasting** was evaluated as a candidate for the epidemic curve but 
  intentionally excluded from the final dashboard: a backtest trained mid-ascent 
  showed the model naively extrapolating exponential growth, with no awareness of 
  susceptible depletion or an approaching peak. This is documented as a deliberate 
  methodological choice, not an omission — general-purpose time series models are 
  not epidemiological transmission models.
- **Small-N suppression**: county-level lethality estimates are flagged as 
  unreliable (greyed out) when the underlying patient count falls below a minimum 
  threshold, to avoid small-denominator rates being visually mistaken for a 
  reliable signal.
